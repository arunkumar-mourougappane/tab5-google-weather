Each gauge shape matches how its metric is actually bounded: Wind gets a compass dial (direction is inherently angular), Humidity a filled capsule (0–100%, reads like a liquid level), UV Index a floating dot on a track (0–11+, position matters more than fill for a scale nobody has memorized), Pressure a semicircle dial (the literal shape of an analog barometer) — all computed from real trig against the sample value, not hand-drawn per reading, same "compute it" approach the Hourly-detail chart's own point positions use. Dew point folds into the Humidity tile (they're read together); Visibility stays a plain inline figure next to Hi/Lo, since a single already-legible number doesn't need a gauge. UV Index reuses the Dashboard's teal/brass/ember severity scale. Air Quality keeps its single-number-plus-scale panel (AQI + category + dominant pollutant), left as-is; Pollen gets its own pill-shaped panel with a 270-degree ring gauge per type (Grass/Tree/Weed) - a real 0–5 Universal Pollen Index, not the 0–4 scale a certain phone weather app's own pollen cards use. Both come from separate APIs not yet wired into src/weather.cpp (see environmental-apis.md). Pressure/Visibility/Dew Point are already returned by the Weather API's own currentConditions:lookup (just not read by weather_parse.h's filter yet) — the closest thing to a "free" addition here.
