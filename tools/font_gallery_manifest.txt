# Manifest for tools/gen_font_gallery.sh - one font/size to generate per
# line, pipe-delimited:
#   lvgl_name|source_font|size_px|symbols|sample|caption
#
# lvgl_name   - must be a valid C identifier, unique across the file.
# source_font - path to a .woff2/.ttf/.otf, relative to the repo root.
#               .woff2 sources are cached and converted to .ttf once per
#               distinct path, even if reused across multiple lines.
# size_px     - passed straight to lv_font_conv --size.
# symbols     - passed straight to lv_font_conv --symbols. Keep subsets
#               narrow (see docs/rendering.md's flash-budget point) -
#               this isn't meant to hold a full Latin charset per size
#               unless the entry specifically needs one (e.g. a label
#               readability test, not a digit-only hero number).
# sample      - text shown on-device in this entry's font. Must only use
#               characters included in `symbols`, or LVGL falls back to
#               its default font (or blank tofu) for whatever's missing.
# caption     - shown on-device under the sample text.
#
# Add a line and rerun tools/gen_font_gallery.sh to test another
# size/family/subset - no code changes needed.

# Full-Latin alphabet ladder, for label text (city name, condition,
# day-of-week, etc.) rather than the hero number. Uppercase+lowercase+
# digits+space+common punctuation.
#
# docs/mockups/dashboard.html's own glyphs (▲/▼ for hi/lo, → for "expand
# →") were tried here first and showed up as tofu/blank boxes on
# hardware - turns out Archivo Variable's cmap has no glyph at all for
# ▲/▼/→/← (confirmed: fontTools' getBestCmap() has no entry for U+25B2,
# U+25BC, U+2192, or U+2190), so lv_font_conv silently emitted empty
# glyphs for them rather than erroring. That's a real mismatch between
# the mockup and the actual font file, not just a test-harness gap - the
# production UI will need either different glyphs Archivo does support
# (it has plain ↑/↓, U+2191/U+2193, just not the filled triangles) or a
# second merged font/raster icon for these specific marks. Testing that
# substitute here: ↑/↓ for hi/lo, plain ">" for the expand affordance.
# Sizes bracket the dashboard mockup's label range (~10-25px at desktop
# ~100 PPI) scaled up for this panel's ~294 PPI (see docs/rendering.md's
# "moved every screen up a tier" precedent, roughly a 2.7-3x factor).
