# Manifest for tools/gen_dashboard_fonts.sh - production fonts for the
# on-device Dashboard screen (src/dashboard_ui.cpp), one line per font,
# pipe-delimited:
#   lvgl_name|source_font|size_px|symbols|compress
#
# lvgl_name   - must be a valid C identifier, unique across the file.
# source_font - path to a .woff2/.ttf/.otf, relative to the repo root.
#               .woff2 sources are cached and converted to .ttf once per
#               distinct path, even if reused across multiple lines.
# size_px     - passed straight to lv_font_conv --size.
# symbols     - passed straight to lv_font_conv --symbols. Narrow subsets
#               only - this is production flash, not a test harness.
# compress    - 1 or 0. Only the two largest/least-frequently-redrawn
#               fonts (hero temp, deg suffix) use LVGL's RLE compression
#               (LV_USE_FONT_COMPRESSED, enabled in include/lv_conf.h) -
#               see docs/rendering.md's guidance that compression is only
#               worth its ~30% render-time cost on large, rare redraws.
#               Every other font stays uncompressed for faster redraws.
#
# One font per exact (size, family, weight) combination actually used in
# docs/mockups/dashboard.html's inline <style> - not a consolidated type
# scale - so two elements that happen to share a pixel size but differ in
# font-weight (e.g. ".hour .temp" at weight 500 vs ".statusbar .right"'s
# default weight 400, both 12.5px) are still two separate generated fonts
# here, not merged.
#
# Sizes are the mockup's OWN px values, unscaled. Correction from an
# earlier version of this manifest: that version multiplied every size by
# ~2.9x on the theory that the panel's ~294 PPI density (vs. a ~100 PPI
# desktop reference) needed compensating for - wrong here, because
# dashboard.html's `.device` frame is already built at exactly 1280x720,
# the panel's own native resolution, not a desktop-scale preview of it.
# Its CSS px are already real device px by construction. Confirmed on
# hardware: the 2.9x version made the whole layout badly overflow its
# 720px height (hero digit alone at 312px, ~4x the panel's own
# `LV_FONT_DEFAULT` of 20px). The ~2.9x precedent in docs/rendering.md
# legitimately applies to the *status/provisioning* screens (their sizes
# were picked freehand, never grounded in a 1280x720-accurate mockup),
# not to this one. Round fractional mockup sizes (13.5, 12.5, 11.5, 10.5,
# 9.5) up to the nearest integer px - lv_font_conv wants an int --size.
#
# Weight picked from each CSS rule's actual `font-weight` (falling back
# to the browser default, 400, where unspecified) - see
# docs/mockups/dashboard.html's inline <style> for the source of truth if
# these ever need re-deriving.
#
# Archivo entries use the variable font's default instance as-is (no
# hand-picked weight axis value) - same simplification already used by
# tools/font_gallery_manifest.txt, not a regression introduced here.

# --- IBM Plex Mono, weight 500 (font-weight:500 in the mockup CSS) ---
# 240/128px, not the mockup's 108/44px - hi/lo moving out of the "now"
# stack (see the info-column rearrange) left a lot of unused vertical
# space below it, per hardware review. Went 108->160->200->240 (hero)
# and 44->64->80->128 (deg) across successive review passes. This size
# triggered a uiTask "Stack protection fault" on hardware (SP pinned at
# the task's stack bound) - root cause was uiTask's 8192-byte stack
# being too small for LVGL's RLE decompression of a glyph this large,
# not the font size itself; fixed by giving uiTask a 16384-byte stack
# (main.cpp, matching netTask's existing size) instead of shrinking the
# font back down.
